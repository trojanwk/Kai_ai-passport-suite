# AI Passport 上的 AIHOT

保留现有 `App::Hot` 协议编号。菜单改为 **AI 热榜**，设备通过 Wi-Fi 直接调用当前匿名 [AIHOT v1 API](https://aihot.news/agent?tab=api)，查看榜单不要求 Mac 助手常开。

## 使用行为

- 上下键选择事件，确认键打开或关闭详情；长按确认沿用现有规则返回菜单。
- 最多显示十个事件，顺序遵循 AIHOT 原始排名。列表右侧数字表示独立信源数量，不使用百度热度、文章总数或自行构造的分数。
- 详情显示标题、事件摘要节选、代表信源和事件最近更新时间，保留 AIHOT 来源标识。
- 页面打开期间每十分钟刷新榜单；同一页面中间隔不足一分钟的刷新请求复用当前榜单。退出后再次进入属于新页面会话。
- 只在打开对应事件详情时请求摘要，在本次页面会话内复用。缺少有效 `links.story` 时显示暂无事件摘要。
- 榜单刷新失败时保留当前页面会话中最后一份完整榜单，不建立持久离线新闻库；退出页面释放内存。
- 限流和边缘安全拒绝不会触发密集自动重试，不更换身份标识或伪装浏览器绕过限制。

## 数据约定与边界

`GET /api/v1/hot-topics` 提供排名、标题、`sourceCount`、代表信源 `source.name`、`latestAt` 以及可选事件链接。仅从校验通过的本站事件链接提取标识，再请求 `GET /api/v1/stories/{publicId}`；摘要优先使用 `digest`，为空时使用 `latest`。返回的事件标识必须与请求一致。

解析器独立于 ESP-IDF 和 LVGL，不保留完整 JSON 树或响应正文，限制嵌套深度、字段缓冲、条目数和文本长度。支持字段乱序、任意分块、转义引号及 Unicode 代理对。无效或不完整的响应不会替换有效榜单。十个事件记录小于 6 KB，解析器小于 3 KB，均由主机测试约束。

应用在 NVS 的 `aihot_actor` 键中保存匿名随机 UUID，不向 AIHOT 发送硬件 MAC、助手配对令牌、Wi-Fi 凭据或账号密钥。现有 ESP32 事件接收器不提供解压缩功能，因此请求不压缩响应，仅保留有界的必要字段。

联网工作继续由现有工作任务负责，按键回调只分发动作。退出页面时取消任务并释放事件记录。分区表、应用偏移、已有 NVS 命名空间及唤醒词模型偏移均保持不变。

## 验证

```bash
.venv/bin/python -m unittest tests/test_passport_aihot.py -v
```

测试使用合成数据验证公开 API 结构，不在仓库重新分发真实新闻内容。覆盖 ASan/UBSan、字段顺序、长文本、Unicode、可选及恶意事件链接、空榜单、信源数、排名或数量不一致、截断 JSON、UTC 和时区时间。在线 API 探测只证明 Mac 网络可达，ESP32 TLS、屏幕渲染、实体按键和离线行为仍需分别实测。
