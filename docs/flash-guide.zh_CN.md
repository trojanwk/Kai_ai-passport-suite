# 安装 AIHOT 固件

版本：**0.5.21-aihot.1**，适用于 AI Passport ESP32-C3、8 MB Flash、无 PSRAM。固件将百度热榜替换为 AIHOT，沿用上游分区定义。生成安装包不会自动刷写设备。

## 应用更新

先核对设备分区与 `manifest.json` 一致：`0x10000` 是 4 MB 的 factory 应用，旧 NVS 位于 `0x9000`，身份数据位于 `0x410000`，存储位于 `0x420000`，应用 NVS 位于 `0x620000`。同型号硬件或 USB 连接成功不能证明分区一致。

确认具体固件和数据影响并获得刷机授权后，应用更新方案只把 `passport_device.bin` 写入 `0x10000`，不写分区表、引导程序、NVS、身份、存储和唤醒词模型，不请求整片擦除。只有现有布局和数据格式兼容时，才能保留现有数据。

使用浏览器时，先解压安装包，再在包所在目录启动本地服务器：

```bash
python3 -m http.server 8769 --bind 127.0.0.1
```

用桌面 Chrome 或 Edge 打开 `http://localhost:8769/`。先暂停 Mac 助手以释放串口，阅读兼容性说明并批准应用更新，再选择 USB 设备。ESP Web Tools 中的 **“Erase device”保持不勾选**。浏览器组件固定为 10.1.1，通过 unpkg 加载，需要联网；固件由本地服务器提供。清单明确要求显示擦除选项，因为该工具对未知固件默认可能整片擦除。

等效的、需要事先批准的 CLI 更新命令：

```bash
python -m esptool --chip esp32c3 -p PORT -b 921600 write-flash \
  --flash-mode keep --flash-freq keep --flash-size keep \
  0x10000 passport_device.bin
```

`PORT` 必须对应已经确认的目标设备。检测到设备不等于已获准刷机。

## 首次安装或不同分区布局

未核对兼容性前，不使用应用更新按钮。`manifest.json` 单独记录了上游首次安装分段：引导程序 `0x0`、分区表 `0x8000`、应用 `0x10000`，以及包中包含时位于 `0x670000` 的唤醒词模型。变更分区表或应用数据格式必须另外说明数据影响。

`merged_flash.bin` 是从 `0x0` 写入的完整镜像，不是应用更新文件；其中填充的间隔可能覆盖旧 NVS。需要保留当前设置时，不使用此文件。安装包的应用更新方案不包含整片擦除。

授权安装后，还需验证开机、中文、AIHOT 加载、详情切换、断网处理，以及原有语音输入和助手连接。镜像合法或写入成功不能代替这些行为的实机验收。
